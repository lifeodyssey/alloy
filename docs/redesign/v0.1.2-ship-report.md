## Lessons Learned for v0.1.3+

### 1. Treat long Codex edit or verify phases as a red flag

Editing or verification phases that run for more than two hours are common
failure signals, not proof of deeper progress. For v0.1.3+, cancel and verify
manually after 30-60 minutes unless the agent is producing fresh, inspectable
evidence.

### 2. Keep conflict handling proportional

Small file-level conflicts are safe for coordinator hand-resolution when the
right policy is obvious. PR #21 was a good UNION case because the goal was to
preserve both branch-local implementation and mainline additions.

Large semantic conflicts should go back to a Codex agent with a narrow prompt,
because preserving both sides mechanically can produce broken behavior.

### 3. Keep GitHub operations with the coordinator

Codex sandboxes may not have a working GitHub token or SSH path. Local file
operations, tests, and commit preparation are good Codex scopes. Release notes,
tag repair, PR creation, and release publishing should stay coordinator-owned.

### 4. Use append-only patterns for shared manifests

`packs/atoms.json` was safe under parallel dispatch because each Codex task
only appended new atoms or added narrow references. Modifying existing atoms
across tasks would have made conflict resolution much riskier.

### 5. Parallel Codex dispatch works with a file-touch matrix

Seven Codex tasks can run in parallel when their write sets are disjoint or
append-only:

- docs vision: README / CLAUDE.md
- changelog: CHANGELOG / package version
- OMO preset: plugin and CLI surface
- agents: agent prompt files
- skills: `universal/skills/alloy-*`
- vendor: vendor, packs, CREDITS
- plan merge: commands, phase naming, migration tests

The coordinator's main job is to preserve the matrix and stop tasks before they
start editing across another task's boundary.
