🎯 SDK / Plugin / Agent 责任分工

Alloy SDK（CLI）
外部进程，install/sync/state 管道
  • 解析 pack/atom 配置
  • 从源仓库 copy 文件到 .opencode/ 和 ~/.config/opencode/
  • 读写 manifest.json（visible/managed/explicit）
  • 读写 state.json（version/installedAt）
  • 读写 .alloy/state/*.jsonl（tasks/evidence/claims）
  • 跑 gate check（读 JSONL 评估）
  • 检测 prereq（colima、container-use 等）
  • 透传 npx skills find 做发现
  • 调 GitHub releases API 查 vendor 更新
  • multi-repo workspace sync
Alloy Plugin（Bun）
运行时进程内，OpenCode hook 注入
  • config hook：boot 时注入 default_agent + MCP
  • chat.message：注入 .alloy/projections/status.md
  • chat.system.transform：当前 task + 未通过 gate 的提示
  • permission.ask：观察 + 拦危险
  • tool.execute.before：正则拦 rm -rf、.env
  • tool.execute.after：每次工具调用写 evidence
  • experimental.chat.messages.transform：按 manifest filter skill（核心）
  • experimental.session.compacting：注入 ledger 摘要防 context 漂移
  • command.execute.before：拦 /add /spec /plan slash command
  • event hook：所有 event 写 runs.jsonl
  • 4 个 tool：alloy_evidence/claim/state/gate（agent 主动调）
Agent（LLM）
实际写代码 + 调工具的智能体
  • Orchestrator 解析用户请求
  • 判定 phase + 派 specialist
  • Specialist 读 SKILL.md 跟纪律
  • 调 OpenCode built-in tool（read/write/edit/bash）
  • 调 MCP tool（context7/postgres/figma 等）
  • 调 plugin tool（alloy_evidence 记录证据）
  • 遵守 phase artifact 约定（写 task_plan.md 等）
  • 遇到 gate fail 回头修，不强推
  • 跨 specialist 通过 git commit / branch handoff
💡 核心原则：SDK 不在运行时跑，Plugin 不写持久状态，Agent 不直接改 manifest。三层各管一段，靠 JSONL/manifest 文件做 IPC。

🔄 3 阶段中央 Pipeline

Plan 阶段
/plan
派 Explorer 读现状
派 Architect 写 plan.md
输出: .alloy/specs/<id>/task_plan.md（强制 ## Spec + ## Plan 双章节）+ findings.md + progress.md
Execute 阶段
/execute
派 Builder（新代码）
或 Fixer（修 bug）
派 Tester（TDD）
输出: 代码 commit + evidence.jsonl 累积 + progress.md 勾选
Verify 阶段
/verify
派 Reviewer（review）
派 Tester（跑测试）
输出: verification.md + 通过 gate 后 alloy_claim 标 done

1 个 Router

Orchestrator
Router

6 个 Specialist（任务类型专精）

Explorer
读懂代码
读现有代码、理解架构、追依赖。可作 sub-agent 委托读后返回摘要给主 agent，省 context。
主要在 Plan 阶段
Architect
写 plan.md
设计决策、技术选型、写 ## Spec + ## Plan 双章节。源覆盖审计。原 alloy-planner 改名。
主要在 Plan 阶段
Builder
新代码
新功能/组件实现。原 alloy-executor 拆出。配合 alloy-tdd 走红绿重构。
Execute 阶段
Fixer
修 bug
先重现 → 最小化 → 根因 → 最小修复 → 回归测试。原 debugger + executor 修 bug 部分合并。
Execute 阶段
Reviewer
评审代码
Code review + critique。Critical / Important / Minor 三档严重度。不能 patch 自己吐槽的代码。
Verify 阶段
Tester
写跑测试
写 test + 跑 test + TDD discipline。原 verifier 改名 + 加强。
Execute + Verify

🌊 关键数据流

1. 用户首次 onboard

$ curl -fsSL alloy/install.sh | bash
  ├─→ 装 alloy CLI 二进制到 /usr/local/bin/alloy
  ├─→ alloy install --target global
  │   ├─→ 从公共 repo clone universal/ 内容
  │   ├─→ 复制 agents/skills/commands 到 ~/.config/opencode/
  │   ├─→ 写 ~/.config/opencode/plugins/alloy.ts
  │   └─→ 写 ~/.config/alloy/state.json
  └─→ shell completion 安装

2. 进入新 repo

$ cd ~/code/my-nextjs-app
$ alloy install
  ├─→ 检测 .alloy/alloy.project.json 或自动推断 scope=frontend
  ├─→ 从公共 repo 复制 scopes/frontend/ 到 .opencode/
  ├─→ 写 .opencode/alloy.manifest.json (visible + managed 列表)
  └─→ 写 .alloy/specs/ 空骨架

3. OpenCode 启动 + plugin 检测

$ opencode
  └─→ OpenCode 读 .opencode/opencode.json
      └─→ 加载 Bun plugin: .opencode/plugins/alloy.ts
          ├─→ config hook: 检查 state.json + manifest 是否最新
          │   └─→ 不是 → 警告 "运行 alloy upgrade"
          ├─→ 注册 11 个 hook
          └─→ 注册 4 个 tool (alloy_evidence/claim/state/gate)

4. 用户跑 /plan 命令

用户: /plan 加密码重置功能
  ↓
command.execute.before hook 拦截
  ↓
派 Orchestrator → 决定 phase=plan → 派 Explorer + Architect
  ↓
Explorer 读现有 auth 模块 (subagent task)
  ↓
Architect 写 .alloy/specs/<uuid>/task_plan.md
  - 强制 ## Spec 章节
  - 强制 ## Plan 章节
  - alloy-plan skill 提供 SOP
  ↓
gate check: 文件存在 + 双章节 ok
  ↓
alloy_evidence 写一条 phase=plan complete 进 evidence.jsonl
  ↓
projections/status.md 更新

5. Vendor skill 升级流

Vercel labs 发 v1.4.0
  ↓ (Renovate 自动每周巡)
Renovate 在我们公共 repo 开 PR
  - vendor.lock.json: vercel-react-best-practices "1.3.0" → "1.4.0"
  - PR description 含 release notes
  ↓
CI 跑 scripts/revendor.mjs
  - 重抓 v1.4.0 内容
  - 重算 sha256
  - 应用 vendor/patches/ 下补丁（若有）
  ↓
我们 review + merge
  ↓
用户下次跑:
  $ alloy outdated
  Vendor skills:
    vercel-react-best-practices: 1.3.0 → 1.4.0  ✓ available

  $ alloy upgrade vercel-react-best-practices
  ✓ 装上了，agent 立刻能用（manifest filter hook 实时生效）

6. /add 单 skill 流（零重启）

用户在 OpenCode 里: /add vercel-react-best-practices
  ↓
command.execute.before hook 拦截
  ↓
plugin 通过 Bash tool 跑: alloy add vercel-react-best-practices
  ↓
manifest.visible 加入 vercel-react
  ↓
下条用户消息触发 chat.messages.transform hook
  - 读最新 manifest
  - 在 <available_skills> 块里露出 vercel-react
  ↓
Agent 这条消息开始能用 vercel-react skill
  → 无需 /exit 重启 OpenCode
