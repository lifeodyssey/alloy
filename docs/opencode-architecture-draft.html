OpenCode Alloy：目标架构

Alloy v2 的核心是 pack 分发、repo-local 安装、MD-first workflow、JSONL state，以及把 GSD/OMO/Superpowers 的精华吸收到 OpenCode native agents、skills 和 gates。

1. Alloy 分发仓库

opencode-alloy 保存可复用能力，不保存业务 repo 的项目状态。
packs/*.json core, frontend, backend, infra, workflow, all
models/*.json 把 planner/executor/reviewer/debugger/verifier 映射到 Copilot、OpenAI 或 local 模型。
vendor/skills + lock 精选第三方 Skill 展开进 repo，来源、license 与 hash 写入 vendor.lock.json。

2. 业务 Repo 的本地安装

setup.sh bash setup.sh --pack frontend --target local --models github-copilot
generates
.opencode/ 只包含当前 repo 需要的 agents、skills、commands、MCP baseline、model mapping。
loads
OpenCode runtime 读取 project-local config；global OpenCode 不被 profile 污染。

3. 不暴露的旧运行时

OMO Slim runtime/plugin 不再提供旧 OMO opt-in。角色路由思想已进入 Alloy agents 和 model maps。
GSD runtime/commands 不再提供旧 GSD pack 或 opt-in。计划、执行、review、verify 被 Alloy state/gates 接管。
npx skills add 默认路径不联网；需要的 Skill 由 repo 直接分发。
skills:["*"] 禁止使用，避免 repo 隔离被全局 Skill 池穿透。

GSD / OMO / Claims

层Alloy 决策修改方式
GSD不再作为运行时分发；吸收计划、执行、review、verify 的门控思想Alloy CLI + state/evidence/gates
OMO Slim不再作为 plugin 分发；吸收多模型角色与 per-agent routingnative Alloy agents + model maps
Claims由 reviewer/verifier 和 gate check 负责事实和完成证据检查JSONL evidence + agent prompt + audit policy
