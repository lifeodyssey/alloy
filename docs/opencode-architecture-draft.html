OpenCode Alloy：目标架构

Alloy 的核心是 profile 分发、repo-local 安装、Hybrid Vendor + Snapshot Overlay，以及把 OMO 的多模型角色思想吸收到 OpenCode native agents。

1. Alloy 分发仓库

opencode-alloy 保存可复用能力，不保存业务 repo 的项目状态。
profiles/*.json core, frontend, backend, infra, workflow-gsd, all
models/*.json 把 planner/executor/reviewer/debugger/verifier 映射到 Copilot、OpenAI 或 local 模型。
vendor + overlays GSD 和第三方 Skill 展开进 repo，Alloy 修改只放 overlay，来源与 hash 写入 lock。

2. 业务 Repo 的本地安装

setup.sh bash setup.sh --profile frontend --target local --models github-copilot
generates
.opencode/ 只包含当前 repo 需要的 agents、skills、commands、MCP baseline、model mapping。
loads
OpenCode runtime 读取 project-local config；global OpenCode 不被 profile 污染。

3. 默认不装的能力

OMO Slim runtime 默认不 vendor、不安装。只保留 experimental/omo-slim 样例。
npx skills add 默认路径不联网；需要的 Skill 由 repo 直接分发。
skills:["*"] 禁止使用，避免 repo 隔离被全局 Skill 池穿透。
